## 3. 真相源与修订联动规则

### 3.1 真相源声明

- **真相源**：`八字静态分析_{1,2,3}.json` —— 命主一切命理判断的单一真相源
- **唯一显式派生**：`file 1::_meta.core_judgments` → `file 3::summary.key_logic`（详见 `file 1::_meta._judgment_authority`）
- **其他产出**（大运整体分析 / 流年分析 / 验前事）是真相源的**消费者**——措辞应与真相源保持一致，但不构成"必须严格联动"的派生

### 3.2 重跑触发判断

下列变化幅度对下游产出的影响（**caveat**：本表为指南，AI 在重跑前应评估改动是机制级还是措辞级，不机械套用——例如 `core_judgments` 改动若仅是措辞精化，下游可只做局部跟进而非整体重跑）：

| 静态分析变化范围 | 大运整体分析 | 流年分析 | 验前事 |
|---|---|---|---|
| 措辞精度 / 跨文件一致性修订 | 局部跟进即可 | 局部跟进即可 | 不影响 |
| `core_judgments` 任一条改动 | 必须重跑 | 必须重跑 | 必须重跑 |
| 用神主线 / 忌神主线改动 | 必须重跑 | 必须重跑 | 必须重跑 |
| 触发钩子新增 / 改动 | 必须跟进 | 必须跟进 | 视命中度判断 |
| methodology 修订 | 视影响判断 | 视影响判断 | 视影响判断 |

> 重跑产物覆盖旧版，依赖 git history，不在文件名加 `_v2`。每次重跑 commit message 注明产出版本号（v1 / v2 / ...）。

## 4. 命名 / 边界

### 4.1 文件命名

- 静态分析：`八字静态分析_{1,2,3}.json`（基础 / 结构 / 演化三件套）
- 大运总览：`大运整体分析_{1,2,3}.md`
- 流年分析：`大运{干支}_流年分析.md`（如 `大运甲午_流年分析.md`），与大运总览**平级**，不放子目录
- 验前事：`验前事.md`
- 原始证据：保留排盘软件原始命名

### 4.2 边界

- `ziwei/`：紫微斗数原始资料，**严格不参与**本目录八字推演
- `南方排八字专业程序.txt`：冻结快照，AI 不直接消费；剔除 / 保留决策落地在 `file 1::_meta.stance_on_software_outputs`
