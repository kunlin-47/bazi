# bazi —— 八字推演框架

子平八字推演的通用框架：从专业排盘软件原始输出出发，经过 AI 化处理生成结构化静态分析文件，再做大运 / 流年 / 验前事等动态推演与反向校验。当前已分析一位命主，框架本身按"通用方法论 + 多命主目录"组织，可扩展。

**只做八字解盘**——排盘由专业软件完成，本仓库不做排盘；原始软件输出（如 `南方排八字专业程序.txt`）作为冻结证据快照保留，AI 不直接消费，所有 AI 化分析以 `八字静态分析_{1,2,3}.json` 为唯一入口（剔除 / 保留决策落在 `_meta.stance_on_software_outputs` 字段）。紫微斗数命盘若有则隔离在命主目录 `ziwei/` 下，**不参与**八字推演。

## 处理链路

```
charts/<命主>/南方排八字专业程序.txt
        ↓
charts/<命主>/八字静态分析_{1,2,3}.json
        ↓
charts/<命主>/大运整体分析.md
        ↓
charts/<命主>/大运{干支}_流年分析.md
        ↓
charts/<命主>/验前事.md
```

> 大致顺序，不强制；`验前事` 与 `流年分析` 也可在静态分析完成后直接做，不必严格按图中线性顺序。

## 三层职责

| 层 | 内容 | 路径 | 变动频率 |
|---|---|---|---|
| 知识层 | 通用八字命理知识与处理规范（跨命主复用） | `methodology/` | 演进式修订 |
| 指令层 | 自包含的 AI 解盘任务指令 | `prompts/` | 跟随任务定义演进 |
| 命主层 | 单一命主的原始排盘 + 静态分析 + 动态产出 | `charts/<命主>/` | 跑测时更新 |

**约束**：通用层（methodology / prompts）不允许写入命主特定结论。命主特定的发现先沉淀在该命主目录，多命主验证有普适性后才升级为通用规则。

## 任务框架

本框架支持的解盘任务全景（**占位表**，反映任务结构与边界，不写进度状态）：

| 层级 | 任务 | 对应 prompt | 命主级产出 |
|---|---|---|---|
| 数据准备 | 原始排盘 → 静态分析 | `prompts/static_extraction.md` | `八字静态分析_{1,2,3}.json` |
| 大运层 | 八步大运总览 | `prompts/dayun_overview.md` | `大运整体分析.md` |
| 流年层 | 单步大运逐年聚焦 | `prompts/流年分析.md` | `大运{干支}_流年分析.md` |
| 反向校验 | 验前事推断 | `prompts/验前事.md` | `验前事.md` |
| 校验闭环 | 已发生事件命中度评估 | `prompts/事件校验.md` | 命主级文档 |
| 主题分析 | 助运 / 发展地点 / 三元九运 | （未规划） | （未规划） |

> 各命主的具体进度、版本、stale 状态见各命主目录的 `README.md`。本表只反映**框架支持的任务全景**，不随进度变化。

## 命名约定

- 通用层（`methodology/`、`prompts/`）用英文命名（已有英文文件不改名，新建文件可中文化）
- 命主目录用命主代号或假名（中文），命主层产出文件用中文命名（如 `八字静态分析_*.json`、`大运整体分析_*.md`）
- 命主目录隔离原则：每个命主一个 `charts/<名>/` 目录，跨命主不共享文件名前缀

## 阅读建议

- 不熟悉八字术语 → 先读 `methodology/basics.md`
- 想看处理"为什么这么过滤"的原则 → 读 `methodology/raw_paipan_processing.md`
- 想看某命主的核心结构判断 → 读 `charts/<命主>/八字静态分析_*.json`
- 想看某命主大运整体走势 → 读 `charts/<命主>/大运整体分析.md`
- 想看反向校验 → 读 `charts/<命主>/验前事.md`
