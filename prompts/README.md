## 设计原则

### 原则 1：自包含

每份 prompt 必须**一份文件读完即可执行任务**，不依赖其他 prompt、不依赖独立的"任务方法论"文件。包括：

- 角色定义
- 任务目标 / 任务定位（含两层架构等设计动机）
- 输入说明（命主数据从哪里读）
- 知识引用（按需查 methodology 哪些**知识**——不是"另一份方法论"）
- 工作流（分几步、每步做什么）
- 论证要求（命理链条、事件描述维度、模糊词禁用、可证伪点等）
- 输出格式（标题层级、必备分区、表格规范）
- 约束 / 边界声明（明确**不**做什么）
- 维护与迭代

### 原则 2：通过引用使用 methodology 知识，不复制

prompt 中需要用到 methodology 中的**知识**（硬数据 / 概念 / 断语字典）时，**指明引用路径**，让 AI 去查：

```
遇到地支藏干判断时，请查 methodology/lookup_tables.md §二。
原局断事时按需查 methodology/传统断语集.md 中适用维度匹配的条目。
```

不要把 `lookup_tables.md` / `传统断语集.md` 等知识库内容粘贴到 prompt 里。
但 prompt 自己的**任务方法论**（边界、论证要求、输出格式等）应直接写在 prompt 内，不再独立成文。

### 原则 3：职责单一 + 边界清晰

一份 prompt 解决一类任务，并且**显式声明"不做什么"**。例如：

- `prompt_大运十年详解.md` 只做八步大运每步十年详解，**不下沉到流年级**
- `prompt_八字静态分析.md` 只做"原始软件输出 → 静态文件"的转换，**不做任何吉凶推演**

任务之间的工作流和输出格式天然不同，强行统一会失去约束力。

### 原则 4：不让 AI 排盘

所有 prompt 都假设排盘已经由专业软件完成，输入是原始排盘文本或已生成的 `八字静态分析_*.json`。prompt 中**不写任何排盘公式或步骤**。

## Prompt 内部结构

每份 prompt 大致包含：角色 / 任务定位 / 边界 / 输入 / 知识引用 / 论证要求 / 产出规模 / 工作流 / 输出格式 / 维护与迭代。新增 prompt 时参照 `prompt_验前事.md`（最新结构）或 `prompt_大运十年详解.md` 的现有结构组织即可，不强制套统一模板。

## 演化机制

prompt 的修订通过 git commit 自然记录。重要原则：

1. **prompt 改动 = 一次产品迭代**：commit message 要写清楚"改了什么、为什么改、预期改进什么"。
2. **重大修订考虑回归**：当一份 prompt 的工作流或输出格式有显著调整时，建议在已有产出上重跑，验证产出质量是否改善。
3. **历史 prompt 不强制保留版本号**：依赖 git history 即可，不在文件名里加 `_v2`、`_v3` 后缀。
