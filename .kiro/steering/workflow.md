# 协作工作流偏好

## Git 工作流

**当前阶段：直接在 `main` 上修改并提交，不走「新分支 + PR」流程。**

理由：仓库还在前期，结构与内容快速演进，PR 仪式带来的开销大于收益。

**何时切换为 PR 流程**：
- 仓库进入"稳定期"——methodology / prompts / 静态分析文件的核心约定基本不再大改
- 出现协作者（不只命主一人维护）
- methodology 修订需要回归测试时

切换的信号由命主主动给出，AI 不要自作主张提议改流程。

## 改动后的同步

直接 push 到 `origin/main`。每次改动后告知命主：
- 改了哪些文件
- commit 哈希
- GitHub 上对应的 commit 链接（方便他在浏览器查看）

## 命主代号约定

本仓库专注于**单一命主**的分析，不引入 `chart_001` / `chart_002` 这类编号目录层。

命主姓名在仓库内为**假名**，直接出现在分析文档中无需脱敏。
