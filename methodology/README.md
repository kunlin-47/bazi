# methodology —— 知识层

## 角色

存放**可复用、跨任务共享**的八字命理知识与处理规范。被 `prompts/` 按需引用，被命主 / AI 作为参考资料。

methodology 是仓库的**核心资产**，演化要谨慎、要有积累——所有 prompts 和命主分析文档都建立在它之上。

## 文件清单

| 文件 | 性质 | 主要受众 |
|---|---|---|
| `basics.md` | 概念解释 + 推理逻辑（散文式） | 人为主，AI 辅读 |
| `lookup_tables.md` | 结构化硬数据（表格 / 矩阵） | AI 必查，人参考 |
| `raw_paipan_processing.md` | **本仓库独有**：原始排盘软件输出 → AI 静态分析文件的处理方法论 | 人 + AI |

## 边界规则

为避免内容重复和职责混乱，严格执行以下分工：

### 规则 1：硬数据归 `lookup_tables.md`

凡是**结构化、可查表、有确定答案**的内容，全部放在 `lookup_tables.md`：

- 十天干 / 十二地支基础属性（阴阳、五行、所属时辰）
- 地支藏干（本气 / 中气 / 余气）
- 十神推导矩阵
- 地支刑冲合害（六冲、三刑、六合、三合、半合、六害）
- 长生十二宫表
- 空亡（旬空）
- 结构机制清晰的神煞（禄神 / 将星 / 华盖 / 文昌 / 驿马 / 羊刃 / 天乙贵人）

### 规则 2：语义和推理逻辑归 `basics.md`

凡是**需要解释、判断、权衡**的内容，放在 `basics.md`：

- 概念定义（日主、月令、用神、格局、空亡、通根等）
- 五行 / 十神在现实中的含义（按本仓库命主"戊土日主"展开）
- 身强身弱判断的逻辑（令、地、势 + 调候）
- 用神判断的多步推理
- 合冲刑害的"剧烈程度"和"现实体感"
- 大运 / 流年的层级关系

### 规则 3：本仓库特有的方法论归 `raw_paipan_processing.md`

xty 等同类项目默认从"已经准备好的 static_chart.json"开始工作。**本仓库多了一步**：从原始排盘软件输出（如《南方排八字专业程序》文本）到 AI 友好的静态分析文件的处理过程。

这一步的核心方法论独立成文：

- 排盘软件"黑箱"输出的识别原则
- 不合理输出的剔除清单
- 神煞过滤原则
- 字段对齐与机制透明化规则
- 静态分析文件的多文件拆分约定

### 规则 4：禁止排盘公式

本仓库的工作流是"软件排盘 + AI 解读"，所以**不收录**：

- 年上起月法、日上起时法
- 起运公式（出生日至节气天数 ÷ 3）
- 节气换月规则的具体计算

这些信息由排盘软件负责，AI 不需要自己算。

### 规则 5：暂不收录的内容（远期再补）

以下 xty 已有但本仓库当前阶段**不做**的内容：

- 助运体系（数字 / 颜色 / 方位 / 贵人方位 / 材质 / 饮食 / 时辰）
- 三元九运专题
- 验前事推断与事件校验

这些可在 methodology 主线稳定后逐步补入；当前优先级是把"原始排盘 → 静态分析 → 大运整体"的核心链路打通。

## 演化机制

methodology 的修订要**保守 + 可追溯**：

1. **修订动机要明确**：每次 commit message 必须说明"为什么改"——是修正错误、补充缺漏、还是吸收实测发现。
2. **流派分歧的处理**：当传统命理多个流派对同一问题答案不一致时，选定一派作为主线，并在文末注明"本仓库采用 X 派 / X 经典作为主线"。本仓库当前主线为**子平派 + 《子平真诠》/《滴天髓》**。
3. **借鉴外部资源时标注来源**：本仓库的 `lookup_tables.md` 与 `basics.md` 框架借鉴自 [`kunlin-47/xty`](https://github.com/kunlin-47/xty) 项目的同名文件，已根据本仓库需要做调整。

## 引用规范

`prompts/` 中引用 methodology 文件时，使用相对路径：

```
methodology/lookup_tables.md
methodology/basics.md
methodology/raw_paipan_processing.md
```

不要在 prompts 中复制 methodology 的内容，始终通过引用，避免双份维护。
