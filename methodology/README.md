# methodology —— 知识层

## 角色

存放**可复用、跨命主、跨任务共享的八字命理知识**——纯知识库，不含任务调度规则。被 `prompts/` 按需引用，被命主目录 / AI 作为参考资料。

methodology 是仓库的**核心资产**——所有 prompts 和命主分析文档都建立在它之上。演化要谨慎、要有积累。

> **边界澄清**：methodology 与 prompts 的分工——
> - `methodology/` = **纯知识层**（命理概念 / 硬数据 / 断语字典等，跨任务复用度高）
> - `prompts/` = **任务自包含**（每个 prompt 含调度 + 工作流 + 任务方法论，AI 一份文件读完即可执行）
>
> "任务方法论"（如怎么做验前事、怎么做大运分析等）属于**任务专属**，归 `prompts/`，不进 methodology。

## 文件清单

| 文件 | 性质 | 主要受众 |
|---|---|---|
| `basics.md` | 概念解释 + 推理逻辑（散文式） | 人为主，AI 辅读 |
| `lookup_tables.md` | 结构化硬数据（表格 / 矩阵） | AI 必查，人参考 |
| `传统断语集.md` | 机制清晰可循的传统命理断语字典（按十神组织 + 维度反查）| AI 按需查询 |

## 边界规则

为避免内容重复和职责混乱，严格执行以下分工：

### 规则 1：硬数据归 `lookup_tables.md`

凡是**结构化、可查表、有确定答案**的内容，全部放在 `lookup_tables.md`：

- 十天干 / 十二地支基础属性（阴阳、五行、所属时辰）
- 地支藏干（本气 / 中气 / 余气）
- 十神推导矩阵
- 地支刑冲合害（六冲、三刑、六合、三合、半合、六害）
- 长生十二宫表
- 空亡（旬空）
- 结构机制清晰的神煞（禄神 / 将星 / 华盖 / 文昌 / 驿马 / 羊刃 / 天乙贵人）

### 规则 2：语义和推理逻辑归 `basics.md`

凡是**需要解释、判断、权衡**的内容，放在 `basics.md`：

- 概念定义（日主、月令、用神、格局、空亡、通根等）
- 五行 / 十神在现实中的含义（以戊土日主为标准教学示例）
- 身强身弱判断的逻辑（令、地、势 + 调候）
- 用神判断的多步推理
- 合冲刑害的"剧烈程度"和"现实体感"
- 大运 / 流年的层级关系

### 规则 3：传统断语字典归 `传统断语集.md`

机制清晰可循的传统命理断语（如枭神夺食、财来破印、伤官见官、印星见冲等）按十神类别组织成字典——是知识，不是任务规则；多个任务（验前事 / 大运分析 / 流年分析）都会查阅。

### 规则 4：禁止排盘公式

本仓库的工作流是"软件排盘 + AI 解读"，所以**不收录**：

- 年上起月法、日上起时法
- 起运公式（出生日至节气天数 ÷ 3）
- 节气换月规则的具体计算

这些信息由排盘软件负责，AI 不需要自己算。

### 规则 5：通用 vs 命主特定

methodology 是**纯通用层**，禁止写入命主特定结论。具体边界：

- ✅ 可以写：以戊土日主为例讲格局取法、空亡实操、用神判断的标准教学举例
- ❌ 不写：某命主的格局判定（如"本造为伤官格 + 佩印之形"）、用神主线、岁运并临年份等命主特定结论
- ❌ 不写：某命主的速查表（禄位、空亡、神煞命中情况）

命主特定的内容写到 `charts/<命主>/` 目录下。当前阶段未做的扩展（助运 / 流年聚焦 / 已发生事件校验等）的范围声明集中在仓库根 `README.md`，本目录不重复。

## 演化机制

methodology 的修订要**保守 + 可追溯**：

1. **修订动机要明确**：每次 commit message 必须说明"为什么改"——是修正错误、补充缺漏、还是吸收实测发现。
2. **流派分歧的处理**：当传统命理多个流派对同一问题答案不一致时，选定一派作为主线，并在文末注明"本仓库采用 X 派 / X 经典作为主线"。本仓库当前主线为**子平派 + 《子平真诠》/《滴天髓》**。
3. **新发现要先写到命主层**：从某个命主的实测中发现某条规则（如"特定结构的火库怎么开"），先写到该命主的分析文档；多命主验证有普适性后才升级为通用规则进入本目录。
4. **任务方法论不进 methodology**：曾经收录的 `验前事方法论.md` 与 `raw_paipan_processing.md` 已分别合并回 `prompts/prompt_验前事.md` 和 `prompts/prompt_八字静态分析.md`（任务自包含）。methodology 现在严守"纯知识层"边界，不再混入任务规则。

## 引用规范

`prompts/` 中引用 methodology 文件时，使用相对路径：

```
methodology/lookup_tables.md
methodology/basics.md
methodology/传统断语集.md
```

不要在 prompts 中复制 methodology 的内容，始终通过引用，避免双份维护。
